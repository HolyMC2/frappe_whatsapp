# META-01 additive schema and transaction decision

`Meta Webhook Receipt` belongs to frappe_whatsapp, already required by doco_marketing. It introduces no new dependency. Both consumers share its unique event key and Pending/Processing/Processed/Failed/Ignored state semantics. Raw payloads are restricted to System Manager and stored once per account-scoped event; generic roles cannot edit/replay them. Diagnostics use IDs, counts and reason codes rather than payload text. No clinical workflow uses this payload store.

The HTTP request owns receipt insertion and its normal transaction commit. It performs no enrichment/send. After-commit enqueue is an optimization; a scheduled bounded sweep recovers committed but unenqueued receipts. A worker commits a Processing lease before enrichment, then holds the receipt row lock during consumption and commits domain writes together with Processed. Failed consumption rolls back only that worker transaction; the committed receipt remains retryable. Expired Processing work may retry **inbound local ingestion and read-only enrichment only**. External sends require the separate native intent/Unknown contract; legacy webhook-triggered bot execution is held until that contract is wired. Replayed/history events never trigger bots.

New schema only; no historical-row backfill, deletion, old bot/run changes, consent grants, or auto-enable. Source/account conflicts remain visible errors. The normal P0 receiver works with this additive table present, making schema-before-runtime a safe rollout step. Do not remove the table on rollback: preserve pending/failed evidence, stop its consumer and keep strict P0 authentication. Marketing receipt adapters require the matching runtime/schema; missing readiness returns an unavailable response instead of silently discarding events.

Lab migration must use the guarded wrapper with complete log retention, inspect orphan/Deleted Document state and verify installed apps beforehand. Restrict staging to an isolated test site or candidate process so unrelated schema work is not synchronized incidentally. After acceptance, integrate runtime/adapters as focused fast-forwards. Production remains a separately authorized rollout.
